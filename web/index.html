Dedicated lighting · L1 and L2

Board-specific switched outputs + two lights + one servo. See the board capability note below. Each light has ambient and event profiles. Event cues temporarily override ambient, then return to it.

Two-wire white strips need separate 3.3V-compatible PWM MOSFET drivers; RGB strips need separate level-shifted DIN connections. Default L1 GPIO14 / TMS, L2 GPIO33 / IO33. Use the strip's rated supply voltage and a shared ground. Never wire LEDs directly to GPIO or use mechanical relays for PWM. Existing shared lightning setups are disabled on upgrade; rewire before enabling. Flashing effects can affect photosensitive viewers.

How to solder or attach wires
  1. Disconnect USB, batteries, and prop power. For boards with fitted headers, use a female jumper or terminal breakout on the correct labeled header pin. You usually do not need to solder wires directly to the board.
  2. If headers are missing, fit 2.54mm headers through the PCB header holes. The side with the metal module is the top; solder the pins to the copper rings on the underside.
  3. For a permanent direct wire, use the correct header through-hole pad. Strip a short end, tin the wire, and solder it to the copper ring. Heat pad and wire together, feed solder into the joint, then remove the iron. Avoid exposed strands or bridging adjacent pads.
  4. Check each joint and neighboring pads for shorts with a meter before power. Add strain relief and keep wiring clear of the antenna.

Solder to the carrier board's header pads, not the tiny chip/module legs, antenna, USB contacts, or shield. GPIO numbers are not sequential physical pin numbers. Grounds for low-side MOSFETs, H-bridge logic, DFPlayer and servo control need the required shared reference; prop and servo power go through their own drivers/supplies.

Named reference layouts covered: classic 30/38-pin boards, WROVER, LOLIN D32, S2, S3, C3, C6, H2. There is no universal diagram for every clone, C3 SuperMini, S2 Mini, ESP32-CAM, XIAO, or other carrier. Use the exact maker/revision diagram for those boards. Reference selection never changes GPIO settings or firmware compatibility.

Simple wiring guide

The GPIO labels below follow your configuration. Fixed GPIO numbers in the example instructions refer to classic ESP32; on another family use the live assignment table and your configured audio/servo pins. GPIO outputs are 3.3V logic signals; use a suitable driver for each load. Test with prop power disconnected first.

Relay module · isolated contacts for a separate load voltage
ESP GPIO → relay IN (must accept 3.3V logic)
ESP GND → module control GND
Module-rated power → VCC
Load supply + → fuse → COM
NO → load +; load − → load supply −

Use NO so the load is off when the relay is inactive. Choose Active LOW or HIGH to match the module. Confirm the input cannot pull the ESP GPIO to 5V. Isolated/JD-VCC modules need their own schematic. Use a DC motor/inductive contact rating adequate for startup/stall current. For a one-way DC load, use appropriate suppression across the motor/pump; the relay-coil diode does not protect the load contacts.

MOSFET module · one-way DC motor or pump
ESP GPIO → module signal / IN
ESP GND → module signal GND and load supply −
Load supply + → fuse → load +
Load − → switched negative / drain
Module power GND → load supply −

This example is for a verified 3.3V-compatible low-side module. Terminal layouts vary; follow your module's diagram. Use the rated voltage/current and inductive suppression. A one-way load diode has its stripe at load + and the other end at load −. Do not place that diode across a reversing motor. Different positive DC supply voltages can use suitable separate MOSFET drivers with a common negative reference.

Sway H-bridge · reversing actuator
12V + → fuse → bridge motor supply +
12V − → bridge power GND; ESP GND → logic GND
Forward GPIO → direction A
Reverse GPIO → direction B
Bridge motor outputs → actuator's two wires

Use a bridge compatible with two Active HIGH direction inputs: A only / B only / both LOW inactive. Check its truth table, enables, logic voltage, motor stall rating, and coast/brake behavior. Enable the software pair interlock; preset dead time is 200ms. Extra enable pins need the module's prescribed wiring. Gravity return on the spine needs a driver that allows it to fall freely when inactive.

Hobby servo · separate regulated power
Configured servo GPIO → servo signal
Servo-rated regulated supply + → servo positive
Supply − → servo GND; ESP GND → supply −

Wire colors vary; use the servo labels. Never power a servo from ESP32 3.3V or connect 12V directly to a typical 5–6V servo. Confirm 3.3V signal compatibility and size the supply for stall current. Calibrate limits with the linkage unloaded. Disarm removes PWM, not servo power.

DFPlayer and trigger
ESP TX GPIO21 → 1kΩ → DFPlayer RX
ESP RX GPIO22 ← DFPlayer TX
Stable 5V → DFPlayer VCC; shared GND
Speaker → SPK1 and SPK2 (neither is ground)
Dry trigger contact → GPIO32 and ESP GND

The DFPlayer and trigger GPIOs are configurable. Default dry contact uses Active LOW with internal pull-up. Powered sensors need an ESP-safe interface; do not apply 5V or 12V to an ESP GPIO. DFPlayer wiring reference ↗

Define an inactive hardware bias during ESP reset, fuse each supply, and provide a physical prop-power cutoff. Exact terminal mapping requires your modules' model/labels; do not infer connections from generic IN/OUT labels.

Hobby servo · extra channel

50 Hz PWM. Default calibration is 1000–2000 μs, with travel limited to 20–160°. Adjust to your servo specification. Arming commands home; after a scene it returns home. Disarming or releasing the live control removes the signal; it does not cut servo power. A live-control connection loss releases PWM within 2 seconds.

Scene behavior · idle life & variations

Idle animation runs while armed, between scares. A trigger interrupts idle, runs a scare, then resumes idle after its gap and cooldown. Idle uses a separate scene and never counts as a scare. Random selection includes all scenes except idle; the assigned scare is used when random is off; choose it with Use this scare for triggers in Build. Idle's automatic scare-track field is ignored: use explicit sound cues if wanted. Outputs still obey pulse limits and direction interlocks.

Motion & timer trigger

Quiet time begins after the scene ends, or when first armed. Stop & disarm cancels repeat. Interlocked directions cannot run together; pulse limits apply to manual tests too.

Skeleton preset: channel 1 spine, 2/3 sway directions, 4 pump, 5/6 spare. Pulse times are starting values for dry testing. Use a motor-rated H-bridge for sway; the direction pair must use Active HIGH inputs. A gravity return motor driver must allow the mechanism to fall freely when inactive.

Pneumatic valve presets

Generate coil cues in the selected scene. Choose valve behavior, channels and timing; then preview and save.

Use a rated relay or MOSFET to switch each DC coil, with flyback suppression. GPIO never powers a valve. Double-coil presets use the one available direction interlock; an existing different motor/valve pair must be reassigned first. Coil-off does not guarantee pressure removal or cylinder return, especially on latching valves. Set pressure and speed with regulator / flow controls. See the included PNEUMATICS-WIRING guide.

Trigger input

Debounced edge trigger: a held sensor cannot keep restarting the scene.

Triggers during a run or cooldown are ignored. The sensor must release before the next trigger. Saving settings requires disarming.

Serial audio player

Player 1: ambient, or ambient/scare on a single module. Enable player 2 for uninterrupted ambient during scares.

Use /mp3/0001.mp3 for track 1 and /mp3/0002.mp3 for track 2 on the DFPlayer microSD. Ambient loops while armed; with player 2 disabled a scare interrupts it. With player 2 enabled, player 1 continues ambient. The scene length decides when ambient resumes. DFPlayer start latency means waveform alignment is approximate. This version sends commands without verified playback feedback.

Player 2 · independent scare audio

Two DFPlayers, two DY-SV8Fs, or one of each. When enabled, player 1 keeps ambient looping and this player handles the scene scare track. Each player needs its own files, power and speaker/amplifier path.

Classic ESP32 example: second UART GPIO4 TX and GPIO34 RX. For another family follow the selected TX/RX fields; one-player boards cannot enable player 2. On your four-row board, underside/USB at bottom: IO4 left outer row 6; IO34 right outer row 6. For DFPlayer, use a 1kΩ series resistor from ESP TX to module RX. Follow the existing DY UART/DIP instructions for either slot. Do not join speaker outputs. Use separate speakers or a proper line-level mixer for one amplifier. GPIO34 is input-only; feed only ESP-safe logic. Both players stop on disarm. Player 2 disabled retains the original single-player behavior. Playback remains command-only.

DY-SV8F · serial or track-trigger pins

Select DY-SV8F in Serial player settings for 9600 baud UART control. Serial uses the existing audio GPIOs and keeps all six prop outputs available. Each module has one playback stream. With a second module enabled, ambient and scare play independently.

Change switches with power disconnected, then power-cycle. On your pictured board, the ON side aligns with H. UART: 1 OFF, 2 OFF, 3 ON. Trigger mode: 1 OFF, 2 ON, 3 OFF. Confirm the printed H/L and CON1–3 markings if using another revision. In trigger mode, IO0–7 select eight tracks by pulling LOW. Use a verified 3.3V-safe interface or transistor/contact to ground. Generic audio presets do not set polarity. BUSY is a status output, not a ninth trigger.

Load files via the player USB port

  1. Disconnect external power/control wiring. Plug a USB data cable into the DY player's Micro USB Download port. Identify its removable drive in File Explorer.
  2. Use MP3 or WAV. A simple WAV starting format is PCM, 16-bit mono, 22,050 Hz; our starter pack uses it. For smaller MP3 files, mono at 96 kbps is a practical starting setting. Renaming does not convert a file.
  3. Use root-level names such as 00001.wav (ambient), 00002.wav (14-second skeleton sequence). MP3 files use the same five digits and .mp3 extension. No /mp3 folder is needed for this guide.
  4. Track selection uses the player's file index, which may follow copy order rather than filename. Back up existing audio, remove only unwanted files deliberately, and copy the intended tracks individually in order. Test track numbers after loading.
  5. Eject the drive, disconnect USB, set UART DIP levels, reconnect the 5V supply/control wiring, and power-cycle. Choose DY-SV8F, enable serial audio, set ambient 1 / scare 2, and save while disarmed.

The DY has about 8 MB onboard audio storage. ESP serial commands control playback; they do not transfer audio files. The ESP web page cannot copy files onto this drive. The numbered-file helper below accepts WAV for DY and MP3 for either player.

Prepare the DFPlayer SD card

  1. Switch off the DFPlayer. Remove its microSD card and put it in a USB card reader.
  2. Use a card of 32 GB or less, formatted FAT32 (not exFAT). Formatting erases a card; back up existing files first.
  3. Create a folder named mp3 at the top level of the card.
  4. Choose a downloaded MP3 below and its track number. Save the numbered copy, then copy it into the card's mp3 folder using File Explorer.
  5. Eject the card, put it back into the unpowered DFPlayer, then power on. Set the same track number in Sound or the scene and save.

This makes a renamed copy; it does not convert WAV / OGG files to MP3, upload audio to the ESP32, or write directly to your card. Load the original file into the waveform reference below for timing. DFPlayer instructions ↗

Current limits

  • The downloadable package contains original synthetic WAV examples. Adding a catalog entry does not copy audio onto a player.
  • DFPlayer playback is commanded without feedback. Sound start latency must be tuned against actual playback. Up to eight timed audio commands per scene are supported; commands on one player need 0.5 seconds separation.
  • Servo angles are commanded positions without feedback. Disarm removes its signal, not its supply power.
  • Controllers operate independently; discovery does not synchronize their scenes.
  • Physical actuator, servo, audio and two-board discovery checks need the corresponding connected hardware.
  • Web controls are operational controls; use a physical power cutoff for prop hardware.
